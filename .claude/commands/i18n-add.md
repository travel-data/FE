--- 
description : 키와 한국어 텍스트를 받아 영어로 번역 후 사용자에게 승인을 받아 시트에 추가
argument_hint : [ns] [key] [한국어 텍스트]
---

대상 시트 : 환경변수 내에 GOOGLE_SHEET_ID, GOOGLE_SHEET_NAME 값 참조
컬럼 순서: A(빈칸) / B(ns) / C(key) / D(ko) / E(en)
입력: $ARGUMENTS

API 호출 규칙 (반드시 준수):

- 시트 읽기(sheets_get_values)는 전체 프로세스에서 정확히 1회만 호출한다.
  이후 모든 삽입 위치 계산은 이 최초 스냅샷 좌표 기준으로 하며, 중간에 재조회하지 않는다.
- 삽입 위치(anchor 행)가 동일한 항목들은 그룹핑하여 하나의 sheets_insert_rows
  호출에 values 배열로 모아 처리한다. 항목 수만큼 개별 호출하지 않는다.
- 여러 그룹을 삽입할 때는 anchor 행 번호 기준 내림차순(아래→위)으로 처리한다.
  최초 스냅샷 좌표를 그대로 사용하며 재계산하지 않는다 — 이 순서를 지키면
  이미 계산한 좌표가 앞선 삽입으로 인해 틀어지지 않는다.
- 승인 전 미리보기 단계(7번)에서는 추가 API 호출을 하지 않는다 —
  2번에서 읽은 데이터만으로 위치/중복 판단을 마친다.

1. 입력은 줄 단위로 구분한다. 각 줄에서 네임스페이스, 번역키, 한국어 원문을 분리한다
   (형식 : `ns key 한국어텍스트` 공백 구분, 파싱 실패 시 어떤 줄인지 알려주고 건너뛴다)

2. mcp-gsheets(sheets_get_values)로 시트 전체의 B열~E열(ns, key, ko, en)을 1회 읽는다.

3. 읽은 데이터를 기반으로 구조를 파악한다
   - ns 컬럼 값이 바뀌는 지점을 기준으로 각 ns의 행 구간 (시작~끝) 을 계산
   - 각 ns 구간 안에서, key 의 첫번째 '.' 앞부분(subgroup)이 같은 행들을
     빈 행 기준으로 서브그룹 블록으로 묶는다

4. 입력된 각 원문을 영어로 번역한다
   - 경주 특화 가이드 서비스, 친근하고 따뜻한 톤 유지
   - 버튼/라벨은 간결한 동사형, 안내 문구는 자연스러운 완전한 문장으로

5. 같은 key가 이미 존재하면 "이미 존재하는 키입니다" 표시 (명시적 승인 없이 덮어쓰기는 하지말 것)
   - 이 판단은 2번에서 읽은 데이터로만 한다 (재조회 없음)

6. 삽입 위치를 다음 우선순위로 결정한다:
   a. 해당 ns + 해당 subgroup 블록이 이미 있으면 -> 그 블록 마지막 행 다음에 삽입
   b. 해당 ns는 있지만 subgroup이 새로우면 -> 그 ns 마지막 행에 빈 행 구분과 함께 새 블록으로 삽입
   c. ns 자체가 새로우면 -> 사용자에게 삽입 위치를 확인 받는다
   같은 anchor 위치로 결정된 입력 항목들은 이 단계에서 미리 그룹핑해둔다
   (8번에서 그룹 단위로 한 번에 삽입하기 위함).

7. 결과를 표로 보여주고 승인을 요청한다:

   | ns     | key      | ko  | en  | 삽입 위치                       |
   | ------ | -------- | --- | --- | ------------------------------- |
   | course | edit.xxx | ... | ... | course/edit 블록 끝 (행 7 근처) |

   승인 / 부분 승인("1,3번만") / 재번역 요청을 받는다.

8. 승인되면, 6번에서 만든 그룹을 anchor 행 번호 기준 내림차순으로 정렬하여 순서대로
   sheets_insert_rows를 호출한다. 그룹당 정확히 1회 호출하며, 같은 그룹 내
   여러 행은 하나의 values 배열로 모아서 보낸다.
   (위쪽부터 삽입하면 아래쪽 행 번호가 밀려서 계산이 꼬이므로 반드시 아래→위 순서.
   최초 스냅샷 좌표를 그대로 쓰며 재계산하지 않는다.)

9. 반영 결과를 요약한다 (몇 건 추가, 몇 건 스킵/거부, 총 API 호출 횟수).
